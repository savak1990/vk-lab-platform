# 012 — ExternalDNS

**Complexity:** Small–Medium
**Risk:** Medium — a misconfigured sync policy can delete a DNS record it doesn't own, including Terraform's ACM DNS-validation record in the same hosted zone.
**Estimated cost:** ~0.5 day · AWS runtime cost: negligible (a controller pod, no additional AWS-billed resource beyond the Route 53 records it manages).
**Recommended model:** Sonnet.
**Depends on:** 002-persistent-foundation (the `lab.<root-domain>` hosted zone), 011-nlb-edge (the NLB/`Service` whose hostname this spec publishes)
**Lifecycle class(es) touched:** Disposable (the controller and every record it creates)

## Scope

ExternalDNS (Argo-managed), publishing Route 53 records inside the
delegated `lab.<root-domain>` hosted zone (spec 002/ADR 0002) for hostnames
such as `grafana.lab.<root-domain>` and `argocd.lab.<root-domain>`, so they
resolve to the NLB from spec 011.

Excludes: the hosted zone and ACM certificate themselves (persistent,
spec 002 — this spec only adds/removes disposable records inside that
zone); the parent/root hosted zone and its NS delegation (external,
constitution §14 — never touched by this spec); the ACM DNS-validation
record Terraform creates in the same zone (spec 002 — explicitly out of
this controller's reach, Requirement 3); any non-DNS concern (the NLB
itself, TLS — spec 011).

## Requirements

1. ExternalDNS owns application-hostname record lifecycle inside `lab.<root-domain>` — this is a hard requirement, not an optional implementation choice. It is the mechanism, not "whichever controller creates the record" (constitution §2, §14).
2. Hostname source MUST be `--source=gateway-httproute` — ExternalDNS reads hostnames directly from the `HTTPRoute` resources spec 010 already authors, and the target address from `Gateway` status. This requires no annotation on any generated `Service`, and no second source of truth for hostnames to drift from spec 010's routing config.
3. ExternalDNS MUST run with a TXT ownership registry (`--registry=txt`), a unique `--txt-owner-id`, and `--domain-filter` scoped to `lab.<root-domain>` only. This is the mechanism that keeps ExternalDNS's sync-mode reconciliation from touching records it did not create — in particular, the ACM DNS-validation record Terraform creates in the same zone (spec 002). `--policy=upsert-only` is explicitly NOT an acceptable substitute for this: it would leave stale/orphaned records behind on `make down`, breaking this spec's own record-cleanup requirement (Requirement 5). The TXT registry + domain filter is the actual guard, not a weaker sync policy.
4. IAM: its own EKS Pod Identity association (new `terraform/modules/external-dns-pod-identity`, same precedent as spec 011 Requirement 9), scoped to `route53:ChangeResourceRecordSets` and `route53:ListResourceRecordSets` on the `lab.<root-domain>` hosted zone's ARN specifically. `route53:ListHostedZones` MUST be granted as `*` — this action does not support resource-level permissions in the AWS IAM API, so this spec does not promise a scoping it cannot deliver; state this explicitly rather than leaving it to be discovered as a deploy-time surprise.
5. Same deletion-ordering discipline as spec 011: ExternalDNS-created records MUST be removed before the controller itself is considered safe to remove, and `make down` MUST leave no orphaned record inside `lab.<root-domain>` behind (constitution §7, "no leaks" postcondition).

## Implementation hints

- `--source=gateway-httproute` requires ExternalDNS's Gateway API support to be enabled/available in the pinned chart version — verify this before relying on it; the alternative (`--source=service` plus a hand-placed `external-dns.alpha.kubernetes.io/hostname` annotation on Envoy's generated `Service`) is available as a fallback but is awkward to own long-term since that `Service` object is generated by spec 010's `EnvoyProxy`, not authored directly.
- Scope IAM tightly: `route53:ChangeResourceRecordSets`/`ListResourceRecordSets` on `arn:aws:route53:::hostedzone/<lab-zone-id>` only, `route53:ListHostedZones` on `*` (see Requirement 4), nothing else. No access to the parent/root zone under any circumstance.
- Test the TXT-registry guard deliberately: run a full `make up` → `make down` → `make up` cycle and confirm the ACM DNS-validation record from spec 002 is untouched throughout — this is the specific failure mode Requirement 3 exists to prevent.

## Testing / acceptance criteria

- After `make up`, `grafana.lab.<root-domain>` and `argocd.lab.<root-domain>` resolve to the NLB's address via Route 53, confirmed via `dig`/`nslookup` against the real zone.
- `make down` removes every record ExternalDNS created inside `lab.<root-domain>`, confirmed via the AWS console/API — no orphaned records remain.
- The ACM DNS-validation record created by spec 002's Terraform is present, unchanged, and untouched by ExternalDNS across a full `make up` → `make down` → `make up` cycle.
- `make up` (after a prior `make down`) recreates the same hostnames' records without any Terraform plan showing drift, and without ExternalDNS reporting ownership conflicts (TXT registry records match the new run's `--txt-owner-id` or are correctly re-adopted).
- Fast validation (Helm/manifest rendering, k8s schema); the TXT-registry/deletion-ordering behavior above is this spec's equivalent of a lifecycle test.
