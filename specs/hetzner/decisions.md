# Decisions

## 1. Accepted starting constraints (from the user, 2026-09-11)

| AWS and Civo regression | both stay byte-identical; golden renders for `aws` and `civo`, `make -n` identity for both |

## 4. Rejected alternatives

- `kube-hetzner` Terraform module: installs CCM, CSI, CNI, cert-manager, autoscaler from Terraform, which violates the Terraform/Argo ownership split and duplicates Argo-owned components.
- `hetzner-k3s` CLI: no Terraform state, so the lifecycle scripts, guards and leak sweeps would have nothing to bind to.
- Hetzner Object Storage for dumps: 6.49 EUR/month minimum against S3 at cents.
- IPv6-only nodes: SSM Parameter Store has no IPv6 endpoint and Hetzner has no managed NAT; one primary IPv4 per node costs 0.50 EUR.
- Floating IP for the LB: the CCM cannot attach one to a load balancer.
- x86 CPX as the default: 3 × CPX22 costs about what Civo costs for less memory; it is the stock fallback only.
- ARM CAX as the default (the 2026-09-11 choice): not orderable in any EU location on 2026-09-19; revisit only if a real `hcloud server create --type cax21` succeeds again and the arm64 image work (HETZ-182) is worth the saving.
- OIDC federation instead of Roles Anywhere: possible on a self-managed control plane but discards six DONE Civo specs; documented as the alternative in ADR 0029's note.
- Static AWS access keys anywhere: forbidden by constitution §5.
- kubeadm + containerd.io + Cilium (the 2026-09-19 choice): about 1,100 lines of new code against k3s's two install lines, with apt repositories and keyrings, a pinned container runtime and its cgroup configuration, a kubeadm v1beta4 document, and a worker join that needs a token minted over SSH — which in turn needed a spec of its own to give the autoscaler a credential. Its one advantage was certification practice against the exam's tool; the operator withdrew that goal on 2026-09-20. Replaced by k3s (ADR 0037, HETZ-017).
- k3s with the SQLite default datastore: costs nothing today at one control plane, but gives no snapshot or restore and cannot become HA without re-initialising the cluster. `--cluster-init` is one flag.
- Cilium in place of k3s's flannel: buys network policy, Hubble and native routing, at the price of `--flannel-backend=none` plus a helm install in cloud-init before any node is Ready. Nothing in `gitops/` needs it today; `--flannel-backend=none` remains the documented route if that changes.
- kOps: free and maintained, with a native Hetzner provider, but that provider is beta and kOps would create the network, firewall and load balancer Terraform owns here, leaving the lifecycle guards and leak sweep nothing to bind to.
- Talos Linux: the cleanest long-term design, with an official Hetzner image, but etcd still needs a `talosctl bootstrap` from the operator's machine — the operator step this design removes — and it adds a toolchain and no SSH to a node.
- Cluster API Provider Hetzner: free and GA, but needs a management cluster first and installs no CNI, CCM or CSI of its own. Built for fleets.
- OKD: free and installable on Hetzner through community tooling, but roughly 128 EUR/month for one node and 369 for three, against constitution §15; its own community tooling warns Hetzner storage misses etcd's latency requirements.
- Cloud Foundry Container Runtime, VMware Cloud PKS and Vagrant: archived in 2022 with no Hetzner BOSH CPI; gone as a product with only proprietary successors and no Hetzner support; and an abandoned 2020 plugin that would still run a bootstrapper inside the VM.
