# CIVO-060 — Civo ingress: Envoy Service LoadBalancer

Spec: `specs/civo/060-civo-ingress-envoy-lb/spec.md`. Depends on CIVO-045 (DONE).

## Context established during planning

Research (code + web) and two advisor passes narrowed this spec's real scope
well below what its prose implies:

- `scripts/argo-up.sh`'s `civo_resolve_inputs()` already resolves both
  `RESERVED_IP` and `FIREWALL_ID` via SSM, and `civo_install_root_application()`
  already passes them as Helm `--set` values. No new SSM/input plumbing.
- `gitops/bootstrap/templates/root-application.yaml` already forwards
  `envoyGateway.reservedIp` / `envoyGateway.firewallId` as Helm `parameters` on
  the root Application. `gitops/values.yaml`'s child chart just needs default
  keys so offline `helm template`/`gitops-check` renders without them set.
- `scripts/argo-down.sh` already tears down any `Service type=LoadBalancer` in
  `envoy` ns generically (not AWS-specific) — no argo-down change needed.
- `gitops/argocd/values.yaml` already carries a custom ArgoCD health check for
  `Gateway` (Lua, checks only `Accepted`/`Programmed`, ignores `ResolvedRefs`)
  — confirmed by direct read, not just subagent paraphrase. No new health
  check needed; the spec's "review amendment" concern about a missing-cert
  Secret causing `Degraded` doesn't apply to this repo's override.
- `scripts/gitops-render-check.sh`'s golden-diff comparison normalizes each
  rendered object to `Kind__ns__name` and sorts keys before diffing — file
  moves cannot perturb the AWS diff. No fixture regeneration needed.

**Resolved spec ambiguity (§4 self-contradiction):** §4's first sentence says
Civo gets an HTTP:80 + HTTPS:443 (`Terminate`, `certificateRefs`) listener
now; its next sentence says "CIVO-070 adds the HTTPS:443 listener." §1 and §2
both agree with the second sentence (traffic is plain HTTP until CIVO-070;
TLS is explicitly out of scope here). Civo's LB is L4 passthrough — a 443
listener without a cert can't mirror AWS's plain-HTTP-on-443 trick, since
AWS's works only because the NLB (out of scope for Civo, no NLB exists)
terminates TLS upstream. **Ruling: Civo gets HTTP:80 only in this spec.**
`listeners` is values-driven so CIVO-070 adding HTTPS:443 is a values change,
not a template change.

**New find not in the spec:** `scripts/gitops-render-check.sh`'s structural
check (`FORBIDDEN_KINDS`) currently forbids `EnvoyProxy Gateway GatewayClass`
uniformly for both `civo` and `local` targets. The moment Civo's branch
renders these, `make gitops-check` fails before any AWS diff even runs. This
check must become per-target: `local` keeps forbidding all three (nothing
changes for it — the `{{- else if eq .Values.target "civo" }}` structure in
Task 1 renders nothing for `local`, same as today); `civo` moves them from
forbidden to required.

## Task 1 — Move and template `gateway.yaml`, split the structural check

**Files:** `gitops/templates/platform/aws/envoy-gateway/gateway.yaml` →
`gitops/templates/platform/shared/envoy-gateway/gateway.yaml`;
`scripts/gitops-render-check.sh`.

- Move the file. Restructure as:
  - `GatewayClass` — unconditional (identical for both targets: same
    `controllerName`, same `parametersRef` to `envoy-proxy-config`). Hoist it
    out of the target branches — this mirrors CIVO-050's pattern of hoisting
    whatever's target-identical into the unconditional part of a shared file.
  - `{{- if eq .Values.target "aws" }}` — `EnvoyProxy`, `Gateway`,
    `ClientTrafficPolicy`: byte-identical to today's content. Do not
    reformat or reorder anything inside this branch — the golden-diff
    normalization makes it safe either way, but an untouched branch is the
    cheapest possible proof of no AWS regression.
  - `{{- else if eq .Values.target "civo" }}` — new:
    - `EnvoyProxy`: `envoyService.annotations` = `kubernetes.civo.com/firewall-id: {{ .Values.envoyGateway.firewallId | quote }}`, `kubernetes.civo.com/ipv4-address: {{ .Values.envoyGateway.reservedIp | quote }}`, `kubernetes.civo.com/loadbalancer-algorithm: round_robin` (hardcoded literal, not a new values key — this isn't Terraform-derived config like `reservedIp`/`firewallId`, it's a fixed platform choice; say so in the code comment only if it clears the 3-line bar, otherwise leave it self-evident).
      Deliberately drop `kubernetes.civo.com/protocol` — CCM's HTTP default is correct for this Gateway; no need to set it explicitly.
    - `Gateway`: single listener, `name: http`, `protocol: HTTP`, `port: 80`, `allowedRoutes.namespaces.from: All`. No TLS block, no HTTPS listener (see ruling above).
    - No `ClientTrafficPolicy` (proxy protocol stays off for Civo; CIVO-190 scope).
  - `{{- end }}` — `local` matches neither branch, renders nothing (same as today).
- `scripts/gitops-render-check.sh`: split `FORBIDDEN_KINDS` per target inside
  `verify_object_set` (a `case "$target"` or target-suffixed variables — pick
  one, keep it consistent with the file's existing style). `civo`: remove
  `EnvoyProxy Gateway GatewayClass` from its forbidden list, and add
  `Application__argocd__envoy-gateway`'s sibling objects — the three new
  Kind__ns__name entries — to `civo`'s `REQUIRED_OBJECTS`. `local`: forbidden
  list unchanged (still forbids all three).
- Verify: `make gitops-check`. AWS diff must stay empty. Civo structural
  check must now require, not forbid, the three Gateway API kinds. Local
  structural check must be unaffected.

## Task 3 — LB-ingress-IP readiness gate in `argo-up.sh`

**File:** `scripts/argo-up.sh`.

- New function, called after the root sync/`civo_install_root_application`
  and before `civo_wait_for_dns` (the DNS wait's own fallback logic assumes
  a resolved LB IP already exists): poll
  `kubectl get svc -n envoy -l gateway.envoyproxy.io/owning-gateway-name=platform-gateway -o jsonpath='{.items[0].status.loadBalancer.ingress[0].ip}'`
  for up to 300s until it equals `$RESERVED_IP`.
- Unlike `civo_wait_for_dns` (always returns 0, non-fatal by CIVO-045
  design), this is a real gate per spec §4/§8: **exit non-zero on timeout.**
  On timeout, print both the expected (`$RESERVED_IP`) and the last observed
  IP (or "none" if the Service has no ingress yet) in the failure message —
  a bare timeout with no diagnosis just gets re-run blind.
- Leave `civo_wait_for_dns`'s own `${...:-$RESERVED_IP}` fallback untouched.
  It sits inside a function whose contract is "always return 0"; removing it
  is a CIVO-045 behavior change this spec doesn't authorize, even though the
  new gate makes it practically redundant.
- Verify offline: `bash -n scripts/argo-up.sh`, shellcheck.

## Task 4 — Live verification on Civo

**Real cloud cost: ~0.2 USD (LB minutes + cluster runtime).**

- First-time or fresh `PROVIDER=civo make up` bootstrap (state → bootstrap →
  persistent → cluster → argo layers, same shape as CIVO-045's live test).
- `curl -H 'Host: argo.civo.<root-domain>' http://<reserved-ip>/` — expect
  the ArgoCD login/redirect page.
- Grafana route: only if observability is present at this milestone;
  otherwise a 404 from Envoy is an acceptable, recorded result per spec §8.
- Port scan the reserved IP. **Expected pass: only 80 open** (§6 step 4 is
  an allowlist against anything *other* than 80/443 — a closed 443 is not a
  failure, since this spec deliberately doesn't open it; see ruling above).
- **Observe and record whether `root` now reaches `Synced/Healthy` on Civo.**
  This is the first Civo spec to add a resource with a real ArgoCD health
  check (the `Gateway`'s `Accepted`/`Programmed` Lua check) — CIVO-045 §8's
  `WATCH_SECONDS=300` workaround exists because nothing in Civo's root tree
  had one. Do not plan to remove the workaround here (out of scope) — just
  record what actually happens (full timeout vs. real convergence, and at
  what elapsed time) so CIVO-120's existing tracking note can be corrected
  with a real observation instead of a guess.
- `PROVIDER=civo make argo-down`: confirm `civo loadbalancer ls` (region
  `LON1`) is empty afterward — the LB must be gone before the cascade
  completes, not just eventually.
- Full teardown afterward (cluster → persistent → bootstrap → state, mirroring
  CIVO-045's discipline) to leave zero ongoing Civo cost.
